# FREEDOM — ระบบจัดการภาพยนตร์และสตรีมมิ่ง

แผงแอดมิน (React + Vite + TypeScript) พร้อมเซิร์ฟเวอร์ Express ที่จัดการ **ล็อกอิน ข้อมูล และ API key** ฝั่งเซิร์ฟเวอร์

## สิ่งที่เปลี่ยนจากเวอร์ชันก่อน

| ปัญหาเดิม | ตอนนี้ |
|---|---|
| รหัสผ่าน `Admin123`/`Staff456` ฝังในโค้ดและกรอกไว้ให้ในหน้าล็อกอิน | ไม่มีรหัสผ่านในโค้ดเลย บัญชีแรกสร้างตอนเปิดเซิร์ฟเวอร์ครั้งแรก (จากตัวแปร `ADMIN_PASSWORD` / `STAFF_PASSWORD` หรือสุ่มให้แล้วแสดงใน console ครั้งเดียว) รหัสผ่านเก็บเป็น scrypt hash |
| เปิดเว็บแล้วเข้าแอดมินได้ทันที (เซสชันถูกตั้งไว้ล่วงหน้า) | ต้องล็อกอินจริง เซสชันอยู่บนเซิร์ฟเวอร์ (cookie HttpOnly) |
| ปุ่ม "เข้าสองบัญชีพร้อมกัน" ข้ามรหัสผ่าน | ล็อกอินบัญชีที่สองต้องกรอกรหัสผ่านของบัญชีนั้น (สูงสุด 2 บัญชีต่อเบราว์เซอร์) สลับได้ด้วย Ctrl+U |
| ข้อมูลอยู่ใน localStorage ของแต่ละเครื่อง | เก็บใน `data/db.json` บนเซิร์ฟเวอร์ ทุกเครื่องเห็นข้อมูลเดียวกัน |
| API key เก็บ/เรียกจากเบราว์เซอร์ | key เก็บบนเซิร์ฟเวอร์ เบราว์เซอร์เรียกผ่าน `/api/proxy/seriesjeen` เท่านั้น |
| ใครก็แก้ข้อมูลได้ | สิทธิ์ตรวจที่เซิร์ฟเวอร์: staff แก้เนื้อหาได้ แต่จัดการผู้ใช้/ตั้งค่า/SEO/FAQ/โฆษณา ได้เฉพาะ admin |
| โฟลเดอร์ `github/` (workflow ไม่ทำงาน) | ย้ายเป็น `.github/` และเปลี่ยนเป็นรันด้วยมือ, merge เข้า branch `sync-upstream` ให้ตรวจก่อน |
| `tsc` error ที่ `import.meta.env` | เพิ่ม `src/vite-env.d.ts` |
| JS ก้อนเดียว 1.4 MB | แยก chunk (react / hls / motion / icons) |

ความปลอดภัยเพิ่มเติม: ล็อกบัญชีชั่วคราวเมื่อกรอกผิด 5 ครั้ง, ตรวจ Origin (กัน CSRF), จำกัดรูปแบบข้อมูลที่รับ, พร็อกซีล็อกให้ไปได้เฉพาะ `api.seriesjeen.online`, ไฟล์ฐานข้อมูลสิทธิ์ 600

## หน้าเว็บผู้ชม + หลังบ้าน (แก้แล้วมีผลทันที ไม่ต้องแตะโฮสต์)

- **`/`** หน้าบ้านสำหรับสมาชิก (ดีไซน์เดียวกับปุ่ม "ดูหน้าเว็บไซต์" เดิม แต่ตอนนี้เป็นของจริง) ดึงข้อมูลจากหลังบ้านโดยตรง ปุ่ม "ดูหน้าเว็บไซต์" ในหลังบ้านจะเปิดหน้านี้ในแท็บใหม่
- **`/admin`** หลังบ้าน (ต้องล็อกอิน)

### หน้าตาหน้าบ้าน

- ธีมของหน้าบ้านอยู่ใน `src/site.css` (ขอบเขต `.site` ไม่กระทบหลังบ้าน) ฟอนต์ Chakra Petch (รองรับไทย)
- **โลโก้:** แทนไฟล์ `public/logo.svg` ด้วยโลโก้ของคุณ (ใช้ชื่อเดิม เช่น `logo.svg`) ข้อความข้างโลโก้มาจาก ตั้งค่า → ข้อความโลโก้ ถ้าพิมพ์สองคำ เช่น `FREEDOM FLIX` คำหลังจะเป็นสีแดง
- ปุ่มเล่นบนการ์ดหนังแสดงตลอดบนจอสัมผัส, เลื่อนด้วยคีย์บอร์ดและกด Enter ได้, มีกรอบโฟกัส, และจะหยุดแอนิเมชันเมื่อผู้ใช้ตั้งค่าลดการเคลื่อนไหวในระบบ

ทุกครั้งที่บันทึกในหลังบ้าน เซิร์ฟเวอร์จะส่งสัญญาณให้หน้าเว็บที่ผู้ชมเปิดอยู่รีเฟรชข้อมูลเองทันที (Server-Sent Events มี polling สำรอง) ไม่ต้องรีโหลดหน้า

| จัดการที่หลังบ้าน | ผลบนหน้าเว็บผู้ชม |
|---|---|
| ภาพยนตร์ (สถานะ active) | แสดงในแคตตาล็อก ส่วน draft/archived ไม่ถูกส่งออกไปจากเซิร์ฟเวอร์เลย |
| แบนเนอร์ | สไลด์หลักหน้าแรก (เปิด/ปิด, ลำดับ, ปุ่มเล่น/รายละเอียด/ลิงก์) |
| ถ่ายทอดสด + การแจ้งเตือน | การ์ดไลฟ์ กระดิ่ง และแถบแจ้งเตือน |
| เมนูหัว/ท้ายเว็บ | เพิ่ม ลบ เรียงลำดับ ซ่อน เปลี่ยนชื่อ (ไทย/อังกฤษ) ลิงก์ไปหมวดหมู่ ไลฟ์ FAQ อีเมลติดต่อ หรือ URL ภายนอก |
| โฆษณา | Pre-roll เล่นก่อนหนัง (ข้ามได้ตามที่ตั้ง), แบนเนอร์สปอนเซอร์ และนับยอดดู/คลิกจริงบนเซิร์ฟเวอร์ |
| FAQ | ส่วนคำถามที่พบบ่อยท้ายหน้า |
| ตั้งค่าทั่วไป | ชื่อเว็บ, ข้อความโลโก้, ลิขสิทธิ์ท้ายเว็บ, อีเมลติดต่อ |
| โหมดปิดปรับปรุง | หน้าเว็บแสดงข้อความปิดปรับปรุง และเซิร์ฟเวอร์หยุดส่งข้อมูลเนื้อหาออกไป |
| SEO | เขียนลงใน HTML ฝั่งเซิร์ฟเวอร์ทุกคำขอ (title, description, keywords, og:*) ให้ Google/ตัวอย่างลิงก์ในแชตเห็นค่าล่าสุดทันที |
| ป้องกันสตรีม (แท็บใหม่ใน ตั้งค่า) | เซิร์ฟเวอร์เซ็นลิงก์ `.m3u8` แบบ TypeA ให้ทุกครั้งที่ผู้ชมกดเล่น กุญแจอยู่บนเซิร์ฟเวอร์เท่านั้น |

สิทธิ์: staff จัดการหนัง/แบนเนอร์/ไลฟ์/แจ้งเตือนได้ ส่วนเมนู โฆษณา FAQ SEO ตั้งค่า ป้องกันสตรีม สมาชิก และผู้ใช้หลังบ้าน เป็นของ admin

## ระบบสมาชิก (หน้าบ้าน ↔ หลังบ้านเชื่อมกันจริง)

ผู้ชมสมัครสมาชิกเองที่หน้าเว็บ (อีเมล + ชื่อที่แสดง + รหัสผ่าน) บัญชีสมาชิก **แยกจากบัญชีแอดมิน/staff โดยสิ้นเชิง** (คนละตาราง คนละ cookie คนละเซสชัน) สมาชิกใช้ cookie แอดมินไม่ได้ และแอดมินไม่ถือเป็นสมาชิก

| ฝั่งหน้าบ้าน | สิ่งที่เกิดขึ้นจริง |
|---|---|
| สมัคร / เข้าสู่ระบบ / ออกจากระบบ | เซิร์ฟเวอร์ตรวจ เก็บรหัสผ่านเป็น scrypt hash ล็อกชั่วคราวเมื่อกรอกผิด 5 ครั้ง จำกัดการสมัครต่อ IP |
| กดเล่นหนัง / ไลฟ์ | **เฉพาะสมาชิก** แขกจะไม่ได้รับลิงก์สตรีมจริงจากเซิร์ฟเวอร์เลย (ไม่ใช่แค่ซ่อนปุ่ม) แล้วระบบเด้งหน้าเข้าสู่ระบบ |
| รายการของฉัน | บันทึกบนเซิร์ฟเวอร์ ตามไปทุกอุปกรณ์ที่ล็อกอิน |
| โปรไฟล์ | เปลี่ยนชื่อ เปลี่ยนรหัสผ่าน (อุปกรณ์อื่นถูกออกจากระบบ) |
| ประกาศแจ้งเตือน | กลุ่มเป้าหมาย `vip` เห็นเฉพาะสมาชิก VIP, `followers` เห็นเฉพาะสมาชิก, `all` เห็นทุกคน (กรองที่เซิร์ฟเวอร์) |

| ฝั่งหลังบ้าน | ผล |
|---|---|
| เมนู **สมาชิก** (admin เท่านั้น) | ดูรายชื่อ ค้นหา กรอง สถิติ เพิ่มสมาชิกเอง ตั้ง/ยกเลิก VIP ระงับ/เปิดบัญชี ตั้งรหัสผ่านใหม่ ลบ |
| ระงับ / เปลี่ยนรหัส / ลบสมาชิก | สมาชิกคนนั้นถูกออกจากระบบทันทีทุกอุปกรณ์ |
| ตั้งค่า → ให้ผู้ยังไม่เข้าสู่ระบบดูรายการหนังได้ | ปิดแล้วแขกเห็นแค่หน้า "สำหรับสมาชิกเท่านั้น" และไม่ได้รับข้อมูลเนื้อหาใดๆ |
| ตั้งค่า → เปิดรับสมัครสมาชิกใหม่ | ปิดแล้วปุ่มสมัครหาย และเซิร์ฟเวอร์ปฏิเสธการสมัคร |

ข้อจำกัดของระบบสมาชิก: ยังไม่มีการยืนยันอีเมลและ "ลืมรหัสผ่านทางอีเมล" (ต้องมีเซิร์ฟเวอร์ส่งอีเมล) ตอนนี้สมาชิกที่ลืมรหัสให้แอดมินตั้งรหัสใหม่ให้ที่เมนูสมาชิก

## ชำระเงินสมัคร VIP (Stripe)

ใช้ Stripe Checkout (หน้าชำระเงินของ Stripe เอง ข้อมูลบัตรไม่ผ่านเซิร์ฟเวอร์ของคุณเลย) รองรับบัตร และ PromptPay ถ้าเปิดใช้ใน Stripe Dashboard ของคุณ

**ตั้งค่า (ทำครั้งเดียว ที่หลังบ้าน):**
1. สมัคร Stripe แล้วคัดลอก **Secret Key** (`sk_test_...` สำหรับทดลอง / `sk_live_...` ของจริง)
2. หลังบ้าน → ตั้งค่า → แท็บ **ชำระเงิน/VIP** → วาง Secret Key → เปิดรับชำระเงิน
3. ใน Stripe Dashboard → Developers → Webhooks → เพิ่ม endpoint เป็น URL ที่หน้าตั้งค่าแสดงให้ (`https://โดเมนของคุณ/api/payments/stripe/webhook`) เลือกเหตุการณ์ `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired` แล้วนำ **Signing secret** (`whsec_...`) มาวางในหลังบ้าน
4. ตั้งแพ็กเกจและราคาในแท็บเดียวกัน (ราคาขั้นต่ำ 10 บาท) ตั้ง `PUBLIC_URL=https://โดเมนของคุณ` ใน `.env` ถ้าเซิร์ฟเวอร์อยู่หลัง proxy

**ระบบทำงานอย่างไร**
- สมาชิกกด "อัปเกรดเป็น VIP" → เซิร์ฟเวอร์สร้างหน้าชำระเงินที่ Stripe → จ่ายเสร็จกลับมาหน้าเว็บ
- VIP ถูกให้ก็ต่อเมื่อเซิร์ฟเวอร์ **ยืนยันกับ Stripe เอง** (webhook ที่ตรวจลายเซ็น + กันส่งซ้ำ, หรือเช็กสถานะ session โดยตรงตอนกลับมา) และ **ยอดเงิน/สกุลเงินตรงกับแพ็กเกจ** URL ที่ปลอมขึ้นมาให้ VIP ไม่ได้
- ซื้อซ้อนระหว่างยังเป็น VIP จะต่ออายุต่อท้ายวันหมดอายุเดิม VIP ที่ซื้อจะหมดอายุเองตามวัน ส่วน VIP ที่แอดมินกดให้จะไม่มีวันหมดอายุ
- แอดมินดูรายการและรายรับได้ในแท็บเดียวกัน

**ข้อจำกัดที่ต้องรู้**
- ทดสอบกับ Stripe จำลองเท่านั้น ยังไม่ได้ทดสอบกับ Stripe จริง **ให้ลองซื้อด้วยคีย์ `sk_test_` ก่อนเสมอ**
- ยังไม่รองรับการคืนเงินอัตโนมัติ (ถ้าคืนเงินใน Stripe ให้ถอด VIP ของสมาชิกที่เมนูสมาชิกเอง) ไม่มีใบกำกับภาษี และรองรับสกุลเงินบาทเท่านั้น
- ตอนนี้ VIP ให้สิทธิ์เห็นประกาศเฉพาะ VIP เท่านั้น **ยังไม่มีหนังเฉพาะ VIP** จึงควรทำต่อก่อนเปิดขายจริง

## ประวัติการดู / ดูต่อ / หน้ารายละเอียดหนัง

- ตัวเล่นหนังจำตำแหน่งที่สมาชิกดูค้างไว้และเปิดต่อจากเดิม (ตัวเล่นแบบ embed บอกเวลาไม่ได้ จะบันทึกแค่ว่าเคยดู) มีแถว "ดูต่อ" ที่หน้าแรก และหน้า "ประวัติ" ที่ลบทีละเรื่องหรือล้างทั้งหมดได้
- หนังทุกเรื่องมีหน้าของตัวเองที่ `/movie/<id>` แชร์/บุ๊กมาร์กได้ ปุ่มย้อนกลับของเบราว์เซอร์ใช้ได้ มีปุ่มแชร์และ "เรื่องที่คล้ายกัน" เซิร์ฟเวอร์ใส่ชื่อ เรื่องย่อ และรูปของหนังเรื่องนั้นลงใน HTML ให้ Google และตัวอย่างลิงก์ในแชตเห็น (เฉพาะเรื่องที่เผยแพร่แล้ว และไม่เผยถ้าตั้งเว็บเป็นสำหรับสมาชิกเท่านั้น)
- เอาข้อความ "คำบรรยายจำลอง" ที่เคยแสดงทับวิดีโอทุกเรื่องออกแล้ว (เมนูเลือกคำบรรยาย/เสียงในตัวเล่นยังเป็นแค่ปุ่มตัวอย่าง ยังไม่ได้เชื่อมกับไฟล์คำบรรยายจริง)

## เริ่มใช้งาน

```bash
npm install
cp .env.example .env      # แก้ ADMIN_PASSWORD / STAFF_PASSWORD (หรือเว้นว่างให้สุ่ม)
npm run dev               # เซิร์ฟเวอร์ :3001 + เว็บ :3000 (เปิด http://localhost:3000)
```

ครั้งแรกถ้าไม่ได้ตั้งรหัสผ่านใน `.env` ให้ดูรหัสที่สุ่มได้จาก console (แสดงครั้งเดียว)

### ขึ้นใช้งานจริง

```bash
npm run build
NODE_ENV=production COOKIE_SECURE=true TRUST_PROXY=true npm start
```

หรือใช้ `Dockerfile` (mount โฟลเดอร์ `/data` เป็น volume ถาวร)

> **สำคัญ:** โฮสติ้งแบบ static (เช่น EdgeOne Pages ที่ใช้อยู่เดิม) รันเซิร์ฟเวอร์นี้ไม่ได้ ต้องใช้โฮสต์ที่รัน Node.js ได้ เช่น VPS, Render, Railway, Fly.io หรือ Docker และต้องใช้ HTTPS

## ตัวแปรสภาพแวดล้อม

ดูรายละเอียดใน `.env.example` (`PORT`, `ADMIN_PASSWORD`, `STAFF_PASSWORD`, `DATA_DIR`, `COOKIE_SECURE`, `TRUST_PROXY`, `ALLOWED_ORIGINS`)

## โครงสร้าง

- `server/` — Express API (`index.ts`), ระบบผู้ใช้/เซสชัน (`auth.ts`), ที่เก็บข้อมูล (`store.ts`)
- `src/` — แผงแอดมิน, `src/services/api.ts` คือตัวเรียก API
- `data/` — ฐานข้อมูลตอนรัน (ไม่ commit; **สำรองไฟล์นี้**)

## ข้อจำกัดที่ควรรู้

- โฆษณา "กลางเรื่อง (mid-roll)" ทำงานเป็นเล่นก่อนหนัง เพราะตัวเล่นแบบ embed แทรกกลางเรื่องไม่ได้
- ป้องกันสตรีมเซ็นที่ลิงก์เพลย์ลิสต์ (`.m3u8`) การตรวจ segment (`.ts`) ยังเป็นหน้าที่ของ CDN/EdgeOne ซึ่งต้องตั้งค่า TypeA ให้ตรงกับในแท็บนี้หนึ่งครั้ง
- แท็บ "EdgeOne HLS Studio" เป็นเครื่องมือจำลอง/ทดสอบการเซ็นและสร้างโค้ดสำหรับ edge ค่ากุญแจในนั้นเป็นค่าตัวอย่าง ไม่ได้เชื่อมกับการตั้งค่าจริงบนเซิร์ฟเวอร์
- ยังไม่มีหน้า "นโยบายความเป็นส่วนตัว/ข้อกำหนด" ในระบบ ให้เพิ่มเป็นลิงก์ภายนอกในเมนูท้ายเว็บ

- ที่เก็บข้อมูลเป็นไฟล์ JSON เหมาะกับแอดมินไม่กี่คน ถ้าข้อมูลหรือจำนวนผู้ใช้โตมาก ควรย้ายไป SQLite/Postgres
- การบันทึกเป็นแบบเขียนทับทั้งคอลเลกชัน ถ้าสองคนแก้หมวดเดียวกันพร้อมกัน คนที่บันทึกทีหลังจะทับ
- เซสชันอยู่ในหน่วยความจำ รีสตาร์ตเซิร์ฟเวอร์แล้วต้องล็อกอินใหม่
- หน้า "ตัวอย่างเว็บไซต์" และตัวเล่นวิดีโอยังเป็นการสาธิตในแผงแอดมิน ไม่ใช่เว็บสาธารณะสำหรับผู้ชม
